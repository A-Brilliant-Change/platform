# Microsoft 365 Brand Library Playbook

## Objective

Align the brand asset library with the platform so that Microsoft 365 Copilot can produce better, more consistent content, presentations, and strategic briefs.

## Recommended SharePoint Structure

```text
Brand Assets/
├── 01-brand/
├── 02-hero/
├── 03-atlas/
├── 04-domains/
├── 05-infrastructure/
├── 06-ecosystem/
├── 07-origin/
├── 08-documentation/
└── 09-approved-placeholders/
```

## Best Practice

- Use the same filenames and folders as the repo
- Upload only approved, production-safe assets
- Keep placeholders separated from final approved assets
- Add short folder-level notes describing usage and intent
- Keep version numbers visible in file names

## Why This Helps

This creates a clean bridge between:

- GitHub Copilot for product, UI, and code work
- Microsoft 365 Copilot for brand storytelling, internal communication, and presentations
- the public-facing website and the internal governance library

## Governance Rule

Any asset used on the website should be represented here before it is used in proposals or executive communication.
